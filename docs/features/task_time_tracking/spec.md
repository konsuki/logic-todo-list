# タスク消化時間計測機能 仕様書

## 1. 誰の、どんな困りごとを解決するのか

- **誰のため**: Todo アプリ（ビジュー）のユーザー本人。
- **困りごと**: 似たタスク A をやった後に似たタスク B を「もっと早くこなしたい」と思っても、**各タスクに実際どれだけ時間がかかったかを後から把握できない**。手作業での時間記録は手間がかかり、継続できない。
- **本タスクの価値**: 「開始 → 一時停止 → 再開 → 完了」のタイムスタンプをボタン操作で自動記録し、実行時間を自動計算することで、タスクごとの消化時間を把握できるようにする。

## 2. データの流れ

### 2-1. 操作の流れ

1. インスペクターの計測エリアで「開始」ボタンを押す → `startAt` を記録。
2. 途中で中断する時は「一時停止」ボタン → `pauses[]` に中断開始時刻を記録。
3. 再開する時は「再開」ボタン → 中断区間を確定（中断開始〜再開の時間を加算）。
4. タスクを完了すると（既存の完了操作） → `completedAt` を記録。
5. 実行時間 = (完了 − 開始) − Σ(中断区間) を自動計算して表示。

### 2-2. 保存先（ノードに新フィールド追加）

各ノードに `timeTracking` フィールドを追加する。

```js
node.timeTracking = {
  startAt: null,      // 開始時刻（epoch ms）
  pauses: [],         // 中断区間の配列 { start, end }（end が null なら「中断中」）
  completedAt: null,  // 完了時刻（epoch ms）
};
```

- 計算ロジックは純粋関数として `features/todo/lib/` に置く（テスト可能にする）。

### 2-3. UI の流れ（インスペクター計測エリア）

- 未開始: 「開始」ボタンのみ表示。
- 計測中: 「一時停止」ボタン表示。経過時間を表示。
- 一時停止中: 「再開」ボタン表示。
- 完了後: タイムスタンプ一覧と合計実行時間を表示。

## 3. 境界条件・例外ケース

- 開始せずに完了 → タイムスタンプなし。実行時間は計算しない（空表示）。
- 一時停止したまま放置 → 「計測中（一時停止）」と表示。完了時は「再開→完了」の区間も中断として扱う。
- 複数回の中断 → 中断区間をすべて合算。
- 完了後に計測エリアは残す（過去の記録を見返せる）。
- 完了を TODO に戻した場合（`toggleStatus` で DONE→TODO）→ 計測データは**保持**する（次の再計測は「開始」からやり直す。過去データは `timeTracking` として残る）。
- 完了操作（`toggleStatus`）で `completedAt` を打刻する際、`completedAt` が既にある場合は上書きしない（初回のみ記録）。

## 4. 優先順位

| 優先度 | 項目 | 本タスクでの扱い |
|--------|------|------------------|
| 必須 | 開始・一時停止・再開のタイムスタンプ記録 | 実装 |
| 必須 | 完了タイムスタンプ（既存の完了操作と連動） | 実装 |
| 必須 | 実行時間の自動計算・表示 | 実装 |
| 必須 | インスペクターへの計測エリア追加 | 実装 |
| 次回 | 改善点エリア（記入・表示） | **スコープ外**（別タスク） |
| 次回 | 過去タスクの計測データ一覧表示 | スコープ外 |

## 5. スコープ外（今回やらない）

- 改善点エリア（intent にある「改善点(=3)」）は別タスク。
- カレンダーへの自動書き込み（これは上位タスクの別子タスク）。
