# 演繹的タスク分解（Deductive Breakdown）機能 仕様書

## 1. 誰の、どんな困りごとを解決するのか
- **対象者**: 複雑な目標やタスクを抱え、具体的にどう手を動かしていいか迷っているユーザー。
- **困りごと**: 現在のAI提案機能は「親と自分のタイトル」しか見ていないため、プロジェクト全体の最終ゴールを見失った一般的な回答になりがち。また、直感的なアイデア出しに留まり、「確実にゴールへ辿り着くための論理的な手順」になっていない。
- **解決策**: 選択中のタスクからルート（最終ゴール）までの文脈を含んだ「ツリー全体」の情報を渡し、与えられた「真なる規則前提を用いた演繹的ワークフロー（`/resolve`）」に従って、AIに客観的かつ厳密な実行手順を考えさせる。そして、その手順を自動的にツリーのノードとして再帰的に追加する。

## 2. 画面やデータの流れ（具体的な形）
### 2.1 UI/トリガー
- インスペクターパネル（`AIInsights.jsx`）内に「演繹的タスク分解」ボタンを配置。

### 2.2 データの流れと処理
1. **ツリー情報の収集**: 
   - 選択中ノードの「ルート（最終ゴール）から現在地までの経路」を構築。
2. **プロンプト構築**:
   - `resolve` ワークフローのルール（真なる規則前提、検証プロトコル等）をシステムプロンプトとして設定。
   - 収集したツリー情報を渡し、「選択中のノードを達成するための手順」をJSON形式で要求。
3. **自動接続（再帰的展開）**:
   - AIから返却されたJSONデータをパース。
   - 既存のツリールール（`addNode` 関数等）を用いて、選択中ノードの配下へ子ノードとして自動追加する。

## 3. 「普通ではないケース」や境界条件
- **JSONフォーマット以外の返却**: 
  - JSONのパースエラーを検知し、UI上に「AIの応答形式が正しくありませんでした。もう一度お試しください」とエラーを表示する。
- **階層の深さ制限**: 
  - AIに対するプロンプトで「最大階層数（例: 3階層まで）」を指定し、無限ループや過剰な細分化を防ぐ。
- **既存の子ノードが存在する場合**: 
  - 既存のノードは上書きせず、提案された手順を末尾に追加（Append）する仕様とする。
- **通信・APIエラー**: 
  - 通信中はローディング表示を行い、タイムアウトやAPIエラー時は処理を中断しエラー文言を表示する。

## 4. 優先順位（実装のスコープ）
- **優先度 高（Must）**
  - ルートから現在地までの文脈抽出。
  - 演繹的ワークフローを用いた厳密なプロンプトの作成。
  - JSON形式での応答パースと、ツリー構造への自動・再帰的なノード追加。
- **優先度 中（Should）**
  - エラーハンドリングとローディングUI。
- **優先度 低（Won't for now）**
  - 追加前のプレビュー・個別選択機能（まずは自動接続に注力する）。
