# 詳細仕様：フォルダ表示（検索・見つけやすさ特化モード）

## 1. 目的

因果関係（順番・依存・親子）を視覚的に見せるのが既存のツリー表示・リスト表示の責務であるのに対し、本機能はそれとは**独立した「フォルダ」という整理軸**を導入し、「見つけたいタスクをすぐ見つけて、すぐインスペクターを開ける」体験を提供する。

- 因果の3関係の視覚化は、引き続きツリー表示・リスト表示の責務として残す（置き換えない）。
- 本機能は、因果とは別の「ディレクトリ管理のような関係」を追加し、その階層を表示基準とする。

## 2. 背景と位置付け

### 2.1 既存の3つの因果関係

| 関係 | 意味 | 例 |
| --- | --- | --- |
| **順番** | 「これをやった後にこれをやる」実行順序（`order`） | Step 1 → Step 2 |
| **依存** | 「これをやったらこれがクリア（着手可能）になる」先行条件（`dependsOn`） | A が完了しないと B を始められない |
| **達成（親子）** | 「これをやったらこれが達成される」因果（`parentId`） | 下位を全部やると上位が達成される |

### 2.2 新規に導入する第4の関係「ディレクトリ（フォルダ）」

- **因果関係は厳密には持たない**。人間の直感的な「まとまり」と認識する単位でタスクを分ける。
- このフォルダの階層を**表示の基準**にする新しいモードを、**リスト表示の中**に追加する。

## 3. 要件

### 3.1 データモデル

- 各ノードに `folderId`（所属フォルダのID）を追加。`null` の場合は「未整理」。
- フォルダは通常ノードと同種のオブジェクトとして同じ `nodes` マップに格納し、`type: 'FOLDER'` で区別する。
- フォルダ同士は `folderId` で親子関係を持つ（ファイルシステム型・単一親）。フォルダの中にフォルダを作れる。
- タスク（GOAL/STRATEGY/ACTION）は、因果上の親（`parentId`）とフォルダ上の親（`folderId`）を**独立に**持つ。
- 進捗計算・ステータスは従来どおり `parentId`（因果）のみを参照し、`folderId` は進捗に一切影響しない。

### 3.2 表示（リスト表示内モード）

- リスト表示のヘッダーに「論理ツリー ⇔ フォルダ」の切り替えトグルを追加する。
- フォルダモードでは、`folderId` を基準に階層を組んで表示する。
  - フォルダはディレクトリのような見た目で表示（アイコン等）。
  - タスクは所属フォルダの下に表示。
  - `folderId` が未設定のタスクは「未整理」配下に一括表示。
- タスク行をクリックすると、既存と同じ `onSelectNode` でインスペクターを開く。

### 3.3 フォルダ操作

- フォルダの追加・削除ができる。
- フォルダの追加は2つの経路から行える：
  - リスト表示の「新規フォルダ」ボタン → ルート直下に作成。
  - フォルダ行の「子フォルダを追加」ボタン → そのフォルダの配下に作成（フォルダの中にフォルダ）。
- タスクをフォルダに割り当てる（インスペクター経由を想定）。
- フォルダ削除時、中のタスク・子フォルダは「未整理」に戻る（タスク自体は削除されない）。

### 3.4 設定（フォルダ登録の強制を回避）

- 設定項目に「フォルダ機能を使う」トグルを追加。
- オフの場合は、フォルダモード自体を表示しない（従来の論理ツリーのみ）。
- これにより、因果の視覚化のみを目的とする人は、タスク作成時にフォルダ登録を強制されない。

### 3.5 検索ボックス（ジャンプ型）

- リスト表示のヘッダーに検索ボックスを追加する。**論理ツリーモード・フォルダモードの両方で表示**する。
- 検索対象は**タイトルの部分一致**（大文字小文字を区別しない）。
- 入力に応じてインクリメンタルに候補一覧（ドロップダウン）を表示する。
- 候補をクリック（または Enter）すると、そのノードまでジャンプする：
  1. 親ノードを自動展開（`openParents`）
  2. スクロール（`scrollTo(id, 'center')`）
  3. 選択（`onSelectNode` → インスペクターを開く）
  4. 既存の選択スタイルでハイライト表示

**検索対象の範囲（現在表示中のモード内に限定）**

- 論理ツリーモード → タスク（GOAL/STRATEGY/ACTION）のタイトル
- フォルダモード → フォルダ名＋タスクのタイトル
- モードをまたぐ横断検索は対象外（将来拡張）。

**境界条件**

- マッチ 0 件 → 候補一覧に「見つかりませんでした」を表示。
- 検索語が空 → 候補一覧を閉じる。
- `deletedAt` / `hidden` のノードは検索対象外。
- フォルダモードの仮想「未整理」ルート（`__unclassified__`）は実在ノードでないため対象外。
- 検索語に正規表現特殊文字が含まれても、単なる文字列として扱う（エスケープ）。

## 4. 境界条件・普通でないケース

- **フォルダ未登録タスク**：`folderId` が `null` のタスクは「未整理」配下に表示。
- **因果とフォルダの二重所属**：タスクは `parentId` と `folderId` を独立に持つ。進捗は `parentId` のみ参照。
- **フォルダ削除**：中のタスク・子フォルダは「未整理」に戻る。タスクは削除されない。
- **ソフト削除・非表示**：既存の `deletedAt` / `hidden` フィルタをフォルダモードでも適用する。
- **フォルダの循環参照**：フォルダを自分自身や子孫配下に移動できない（既存 `checkCircularDependency` と同様の防止）。

## 5. 優先順位とスコープ

### MVP（今回実装）

1. フォルダをデータとして持てる（`folderId` / `type: 'FOLDER'` / 追加・削除）
2. リスト表示内トグルでフォルダ階層を表示
3. タスクをフォルダに割り当て（インスペクター経由）
4. 設定「フォルダ機能を使う」トグル

### 将来拡張（今回は対象外）

- 検索の description / intent 対応
- 複数キーワード・AND/OR 検索
- 論理モード ⇔ フォルダモードをまたぐ横断検索
- フォルダ内のDnD並び替え
- フォルダリネーム・フォルダの並び替え

## 6. 影響範囲と注意

- `treeLogic` の進捗計算・`parentId` ベースのロジックには**変更を加えない**。
- 既存の OR 関係の `groups`（代替手段のまとまり）とは別概念。混同しない。
- 一括インポート・MCP エクスポート等の既存機能が `folderId` / `FOLDER` ノードに耐えられるか確認する（未知フィールドを無視するか、別途対応が必要か）。
