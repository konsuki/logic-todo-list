# 代替手段（OR型分岐）表現機能 仕様書

## 概要
親タスクの配下に「同一目標を達成するための複数の代替手段（どちらか一方で十分）」を表現できるようにする。現状は親の完了が「全子の完了（AND）」で決まるが、これを「いずれかのグループの全完了（OR）」でも表現できるように拡張する。

---

## 背景・目的
**誰の、どんな困りごとを解決するか:**
- ユーザーが「この目標は、手段A（B・C・D）か手段B（E・F・G）のどちらかで達成できる」という、互いに代替可能な複数手段を計画したいときに、現状では表現できない。
- 現状は全子完了でしか親が完了扱いにならないため、一方の手段だけで目標を達成しても、もう一方の未着手手段が「やるべきタスク」として残り続け、目標が達成済みなのに未完了と表示される（誤った完了判定）。

**論点分解の結論（本仕様の根拠）:**
- OR は「グループ単位の OR」：グループ内は AND（全完了でグループ達成）、グループ間は OR（いずれかのグループ達成で親達成）。
- 進捗計算は「最良グループ方式」：OR ノードの progress = 各グループ進捗（グループ内平均）の最大値。
- データモデルは「属性付与方式」（既存ノードに `relation` と `groups` を追加）。

---

## データモデルの変更

### 追加フィールド: `relation`
- **型**: `'and' | 'or'`（省略時は `'and'`）
- **意味**: そのノードが配下の子タスクをどう完了判定に使うかを表す。
  - `'and'`: 全子の完了で自身が完了（従来どおり）。
  - `'or'`: 配下のいずれかのグループが達成されれば自身が完了。
- **適用対象**: 子を持つ中間ノード（STRATEGY / GOAL）。葉ノード（子なし）では意味を持たない。

### 追加フィールド: `groups`
- **型**: `string[][]`（子 ID の配列の配列）。省略時は `[]`。
- **意味**: `relation === 'or'` のときのみ有効。各要素が 1 つの「代替手段グループ」を表し、グループ内は AND、グループ間は OR。
  - 例: `groups = [["B", "C", "D"], ["E", "F", "G"]]` は「BCD か EFG のどちらかで十分」を表す。
- **制約**: 各子 ID は 1 つのグループにのみ属する。`groups` に含まれない子は、`relation === 'or'` では 1 つの単独グループとして扱う（後方互換・未分類子の安全策）。

---

## 機能要件

### 1. 進捗計算（OR 対応）
`calculateNodeProgress`（`src/logic/treeLogic.js`）を拡張する。

- **AND ノード**（`relation !== 'or'`）: 従来どおり「全アクティブ子の progress の平均」。
- **OR ノード**（`relation === 'or'`）:
  1. 各グループの進捗を、グループ内の全アクティブ子の progress の平均として計算する。
  2. 親の progress を、それらグループ進捗の**最大値**とする。
  3. グループが 0 個（子なし）の場合は、従来の葉ノード扱い（status DONE なら 100、それ以外 0）。
- アクティブ子の判定（`deletedAt` / `hidden` の除外）は従来どおり。

### 2. 完了判定（整合性の担保）
- 進捗計算を上記のとおりにすることで、OR ノードは「いずれかのグループの全子が DONE（グループ進捗 100%）」になった時点で progress 100% → status DONE になる。
- これにより「完了 ⇔ 100%」の整合性と、「子を完了させるたびに進捗が減らない」単調性が保たれる。

### 3. Inspector「How?」での関係切替 UI
- 「How?」セクションに、選択中ノードの子関係を切り替える操作を追加する。
  - AND / OR のトグル（選択中ノードが子を 2 つ以上持つ場合に有効）。
- OR に切り替えたときのグループ分け UI（最小構成）:
  - 各子タスクをグループに分ける操作を提供する。ただし、まずは「単純に各子を 1 つの単独グループとして扱う」デフォルト状態から始め、グループ編集は後続の拡張とする。
  - 本スコープでは、OR 切替時に「各子が独立した代替手段（＝いずれか 1 つで十分）」という最も単純な OR を表現できることを担保する。

### 4. 後方互換性
- `relation` / `groups` を持たない既存ノードは、`relation === 'and'` として扱う。
- 既存データのマイグレーションは不要（省略時のデフォルトで従来動作を維持）。

---

## UI 仕様

### Inspector「How?」セクション
- 子を 2 つ以上持つ中間ノードを選択中に、関係種別（AND / OR）を示すトグルを表示。
- トグルを OR にした場合、子タスク一覧を「代替手段」として区切って表示し、各子が独立した代替手段であることを視覚的に示す（区切り線・ラベルなど）。
- トグルを AND に戻した場合は従来の子一覧表示に戻る。

---

## 境界条件・非対応ケース

| ケース | 扱い |
| --- | --- |
| 子が 0 個（葉ノード） | `relation` / `groups` は無効。従来の葉ノード進捗計算を適用。 |
| 子が 1 個のみ | AND と OR の区別が結果に現れないため、トグルを無効化（または非表示）。 |
| 子が 2 個以上 | AND / OR トグル有効。 |
| `groups` に含まれない子 | OR 時は「1 つの単独グループ」として扱い、進捗計算に含める。 |
| `relation === 'or'` だが `groups` が空 | 全子を「各子 1 つずつの単独グループ」として扱う（＝「いずれか 1 つで十分」）。 |
| OR から AND へ切替 | `groups` を `[]` にリセットし、進捗を再計算。 |
| 既存データ（`relation` / `groups` なし） | `relation === 'and'` として従来動作を維持。 |
| `hidden` / `deletedAt` の子 | 進捗計算・グループ集計から除外（従来のアクティブ子判定）。 |
| OR ノードの親完了後の残グループ | 本スコープでは視覚的なグレーアウトは行わない（進捗計算の正しさを優先。表示は後続拡張）。 |

---

## 制約・注意事項
- `groups` のグループ編集 UI（ドラッグ＆ドロップ等）は本スコープ外。まずは「各子＝独立した代替手段」の OR を扱う。
- ツリー表示（TreeView / ListView）でのグループ区切り表示は本スコープ外。Inspector の「How?」に限定する。
- 進捗計算の変更は既存の全ビュー（TreeView / ListView / Inspector）に波及するため、`calculateNodeProgress` の変更が正しく全箇所に効くことを確認する。
- i18n 対応: 関係種別のラベル（AND / OR、代替手段など）は日本語・英語両方で翻訳キーを追加する。
