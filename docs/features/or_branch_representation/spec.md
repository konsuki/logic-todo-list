# 代替手段（OR型分岐）表現機能 仕様書

## 概要
親タスクの配下に「同一目標を達成するための複数の代替手段（どちらか一方で十分）」を表現できるようにする。現状は親の完了が「全子の完了（AND）」で決まるが、これを「いずれかのグループの全完了（OR）」でも表現できるように拡張する。

---

## 背景・目的
**誰の、どんな困りごとを解決するか:**
- ユーザーが「この目標は、手段A（B・C・D）か手段B（E・F・G）のどちらかで達成できる」という、互いに代替可能な複数手段を計画したいときに、現状では表現できない。
- 現状は全子完了でしか親が完了扱いにならないため、一方の手段だけで目標を達成しても、もう一方の未着手手段が「やるべきタスク」として残り続け、目標が達成済みなのに未完了と表示される（誤った完了判定）。

**論点分解の結論（本仕様の根拠）:**
- OR は「グループ単位の OR」：グループ内は AND（全完了でグループ達成）、グループ間は OR（いずれかのグループ達成で親達成）。
- 進捗計算は「最良グループ方式」：OR ノードの progress = 各グループ進捗（グループ内平均）の最大値。
- データモデルは「属性付与方式」（既存ノードに `relation` と `groups` を追加）。

---

## データモデルの変更

### 追加フィールド: `relation`
- **型**: `'and' | 'or'`（省略時は `'and'`）
- **意味**: そのノードが配下の子タスクをどう完了判定に使うかを表す。
  - `'and'`: 全子の完了で自身が完了（従来どおり）。
  - `'or'`: 配下のいずれかのグループが達成されれば自身が完了。
- **適用対象**: 子を持つ中間ノード（STRATEGY / GOAL）。葉ノード（子なし）では意味を持たない。

### 追加フィールド: `groups`
- **型**: `Array<Group>`（省略時は `[]`）。各 `Group` は以下のオブジェクト形式。
  ```js
  { id: "g1", name: "予算重視", color: "#4F8CFF", children: ["B", "C"] }
  ```
- **意味**: `relation === 'or'` のときのみ有効。各 `Group` が 1 つの「代替手段グループ」を表し、グループ内は AND（全子完了でグループ達成）、グループ間は OR（いずれかのグループ達成で親達成）。
  - 例: `groups = [{children:["B","C"]}, {children:["D","E","F"]}]` は「(B かつ C) か (D かつ E かつ F) のどちらか」を表す。
- **後方互換**: 従来の `string[]`（子 ID の配列）形式の要素も `normalizeGroups` がオブジェクト形式に正規化して解釈する（`children` 相当として扱う）。
- **制約（相互排他）**: 各子 ID は高々 1 つのグループにのみ属する。これは UI の単一選択セレクトと、`assignChildToGroup` の実装（割り当て先以外のグループから子 ID を除去）の両方で構造的に保証される。`groups` に含まれない子（未分類）は、進捗計算上は 1 つの単独グループとして扱う。

---

## 機能要件

### 1. 進捗計算（OR 対応）
`calculateNodeProgress`（`src/logic/treeLogic.js`）を拡張する。

- **AND ノード**（`relation !== 'or'`）: 従来どおり「全アクティブ子の progress の平均」。
- **OR ノード**（`relation === 'or'`）:
  1. 各グループの進捗を、グループ内の全アクティブ子の progress の平均として計算する。
  2. 親の progress を、それらグループ進捗の**最大値**とする。
  3. グループが 0 個（子なし）の場合は、従来の葉ノード扱い（status DONE なら 100、それ以外 0）。
- アクティブ子の判定（`deletedAt` / `hidden` の除外）は従来どおり。

### 2. 完了判定（整合性の担保）
- 進捗計算を上記のとおりにすることで、OR ノードは「いずれかのグループの全子が DONE（グループ進捗 100%）」になった時点で progress 100% → status DONE になる。
- これにより「完了 ⇔ 100%」の整合性と、「子を完了させるたびに進捗が減らない」単調性が保たれる。

### 3. Inspector「How?」での関係切替 UI
- 「How?」セクションに、選択中ノードの子関係を切り替える操作を追加する。
  - AND / OR のトグル（選択中ノードが子を 2 つ以上持つ場合に有効）。
- OR に切り替えた場合、子タスクをグループ分けする操作を提供する。

### 4. Inspector「How?」でのグループ編集 UI（今回追加）
OR モード時に、以下の操作・表示を提供する。

#### 4-1. グループ追加・削除
- 「＋グループを追加」ボタンでグループを 1 つ追加する。
- 追加時、名前は「グループN」（N は連番）、色はパレットから自動割り当てする。
- 各グループカードに削除ボタンを設ける。削除するとそのグループに属していた子は「未分類」に戻る。

#### 4-2. 子タスクのグループ割り当て（相互排他）
- 各グループカード内に、選択中ノードの子タスク一覧を「所属選択」として表示する。
- 各子タスクは「所属グループ」を単一選択のセレクト（なし / グループ1 / グループ2 …）で指定する。これにより相互排他が構造的に保証される。
- セレクト操作は `assignChildToGroup(nodeId, childId, groupId | null)` に集約し、割り当て先以外のグループからも該当子 ID を除去する（二重所属の防止）。

#### 4-3. 便利な工夫（4項目）
1. **グループ色分け**: 各グループに色を自動割り当てし、グループカードと所属子の表示に色を反映する。
2. **グループ名（ラベル）**: グループ名をインライン編集可能にする（デフォルト「グループN」）。
3. **グループ進捗率表示**: 各グループカードに進捗率（グループ内のアクティブ子の平均 progress）を表示する。
4. **グループ折りたたみ**: 各グループカードを折りたたみ・展開可能にする。

### 5. 後方互換性
- `relation` / `groups` を持たない既存ノードは、`relation === 'and'` として扱う。
- `groups` の要素が旧形式（`string[]`）のデータも、`normalizeGroups` がオブジェクト形式へ正規化して解釈する。
- 既存データのマイグレーションは不要（省略時のデフォルトで従来動作を維持）。

## UI 仕様

### Inspector「How?」セクション
- 子を 2 つ以上持つ中間ノードを選択中に、関係種別（AND / OR）を示すトグルを表示。
- トグルを OR にした場合、グループ編集 UI を表示する（下記）。
- トグルを AND に戻した場合は従来の子一覧表示に戻る。

### グループ編集 UI（OR モード）
- 関係トグルの下に「＋グループを追加」ボタンを表示。
- 各グループをカードで表示。カードには以下を含む：
  - 色インジケータ（割り当て色）
  - グループ名（インライン編集可能）
  - 進捗率表示
  - 折りたたみボタン
  - 削除ボタン
- 各グループカード内に、子タスクの「所属グループ」セレクトを表示（単一選択で相互排他を担保）。

## 境界条件・非対応ケース

| ケース | 扱い |
| --- | --- |
| 子が 0 個（葉ノード） | `relation` / `groups` は無効。従来の葉ノード進捗計算を適用。 |
| 子が 1 個のみ | AND と OR の区別が結果に現れないため、トグルを無効化（または非表示）。 |
| 子が 2 個以上 | AND / OR トグル有効。グループ編集 UI を表示。 |
| `groups` に含まれない子（未分類） | 進捗計算上は「1 つの単独グループ」として扱う。UI では「なし」選択状態として表示。 |
| `relation === 'or'` だが `groups` が空 | 全子を「各子 1 つずつの単独グループ」として扱う（＝「いずれか 1 つで十分」）。UI は未分類状態を表示。 |
| グループを 0 個にした場合 | 全子が未分類（＝各子が単独グループ）に戻る。 |
| 空のグループ（子 0 個） | 進捗計算では無視。UI ではカードを表示し続け、削除を促す。 |
| OR から AND へ切替 | `groups` を `[]` にリセットし、進捗を再計算。 |
| 既存データ（`relation` / `groups` なし） | `relation === 'and'` として従来動作を維持。 |
| 旧形式 `groups`（`string[]` 要素） | `normalizeGroups` でオブジェクト形式へ正規化して解釈。 |
| `hidden` / `deletedAt` の子 | 進捗計算・グループ集計から除外（従来のアクティブ子判定）。 |
| OR ノードの親完了後の残グループ | 本スコープでは視覚的なグレーアウトは行わない（進捗計算の正しさを優先。表示は後続拡張）。 |

---

## 制約・注意事項
- グループの色はパレットから自動割り当てする。手動での色変更は後続拡張。
- ツリー表示（TreeView / ListView）でのグループ区切り・色分け表示は本スコープ外。Inspector の「How?」に限定する。
- 進捗計算の変更は既存の全ビュー（TreeView / ListView / Inspector）に波及するため、`normalizeGroups` / `calculateNodeProgress` の変更が正しく全箇所に効くことを確認する。
- i18n 対応: グループ追加・グループ名・進捗率・折りたたみ・所属選択などのラベルを日本語・英語両方で翻訳キーを追加する。
