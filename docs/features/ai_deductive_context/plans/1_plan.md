# 実装プラン: 演繹的タスク分解のコンテキスト強化

このプランは、「演繹的タスク分解」機能において、AIに渡すプロンプトのコンテキストを強化し、プロジェクトの全体像と完了の前提条件を伝えるためのものです。

## 大まかな手順

1. **ツリー構造のテキスト化ロジックの追加**
   - `useAI.js` 内に、再帰的にツリーをテキスト化するローカル関数 `formatTreeAsText(nodes, nodeId, depth = 0)` を追加します。
   - この関数は、指定ノードのタイトルと説明（ある場合）をインデント付き（`'  '.repeat(depth) + '- ' + title + ' (説明: desc)'`）で返し、子ノードがあれば再帰的に呼び出して結合した文字列を返します。説明文内の改行は半角スペースに置換します。
   - `getDeductiveBreakdown` 内の文脈収集処理（`while` ループ）を拡張し、最上位ノードの ID (`rootId`) を取得できるようにします。
   - 取得した `rootId` を起点に `formatTreeAsText` を実行し、全ツリーのテキスト表現（`treeContextText`）を生成します。

2. **getDeductiveBreakdown のプロンプト改修**
   - `systemPrompt` の【基本定義】に、「親タスクについている子タスクを全て実行すると、親タスクが完了したことになる」という関係性を追加します。
   - `userMessage` を更新し、「現在のプロジェクトの全体像（前提となるフロー）:」として生成した `treeContextText` を埋め込みます。
   - 同じく `userMessage` の指示部分を、「この前提フローを踏まえた上で、現在選択中の目標タスク「〇〇」の配下に作成すべきタスクを分解・出力してください」に変更し、AIに要求を明確化します。
   - `aiApi.js` の `sendChatMessage` に `newChat` および `modelType` 引数を追加し、リクエストの JSON ボディに `new_chat: newChat`, `model_type: modelType` を含めるよう修正します。
   - `getDductiveBreakdown` 内で `sendChatMessage` を呼び出す際、第3引数に `true` (新規セッション) を、第4引数に `'expert'` (シンキングモード) を指定し、常に高度なR1思考プロセスによる演繹分解を実行させます。

3. **動作確認**
   - 複数階層の子ノードを持つツリーを作成し、中間ノードを選択して「演繹的タスク分解」を実行します。
   - 送信されるプロンプトに、ルートからの全ツリー構造がインデント付きで含まれていることを確認します。
   - AIからの提案が、既存の前提フロー（他の兄弟タスクや既存の子タスク）と矛盾せず、選択中のタスクの達成に必要な手順を正しく分解していることを確認します。
