# 仕様書: 演繹的タスク分解のコンテキスト強化

## 1. 概要
「演繹的タスク分解」機能において、AIに渡すプロンプトのコンテキストを強化します。具体的には、対象タスクが属する最上位ゴール以下の**全ツリー構造**をフロー形式のテキストとして渡し、「親タスクを完了するにはすべての子タスクを実行する必要がある」という前提を明記することで、既存のタスクと矛盾しない最適なタスク分解を実現します。

### 解決する課題
- AIが現在のプロジェクトの全体像（他のタスクや実行順序）を把握できていないため、的外れな提案や重複したタスクが生成される問題を解決します。

## 2. データフローの変更 (`useAI.js`)
### 2.1 ツリー構造のテキスト化
- 選択中ノードから親を辿り、最上位のルートノードを特定します。
- ルートノードから再帰的に子ノードをたどり、インデント付きのリスト形式（例: `- 目標\n  - タスクA\n  - タスクB`）のテキストを生成するロジックを追加します。

### 2.2 プロンプトの改修
- **システムプロンプト (基本定義)**
  - 「親タスクについている子タスクを全て実行すると、親タスクが完了したことになる」という関係性を【基本定義】に追記します。
- **ユーザープロンプト (文脈と指示)**
  - 「現在のプロジェクトの全体像（前提となるフロー）:」として、生成したツリーテキストを埋め込みます。
  - 「この前提を踏まえた上で、現在選択中のタスク『〇〇』の配下に作成すべきタスクを出力してください」と指示を具体化します。

### 2.3 新規チャットおよびシンキングモードでのリクエスト指定
- `aiApi.js` の `sendChatMessage` に `newChat` および `modelType` 引数を追加し、APIへのPOSTボディに `new_chat: newChat` と `model_type: modelType` を含められるように拡張します。
- `useAI.js` からの「演繹的タスク分解」のリクエスト時に `newChat=true`, `modelType="expert"` を指定し、API側で常に新規チャットセッションを開始し、シンキングモード（ディープシンキング思考モデル / R1）を使用して高度な演繹的推論を実行させます。これにより過去の履歴の混入を防ぎ、より論理的に正しいタスク分解を実現します。

## 3. 境界条件・特記事項
- **ツリーサイズ**: トークン数制限を防ぐため、渡す情報はタスクの「タイトル」、階層構造（インデント）、および「説明（description）」のみとします。説明文は改行をスペースに置換して1行に整形します。
- **ルートノード選択時**: 選択したノード自体がルートの場合も、自身以下のツリーが正しく渡るようにします。
