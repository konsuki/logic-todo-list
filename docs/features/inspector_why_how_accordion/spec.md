# インスペクター：Why?/How? アコーディオン化 仕様書

## 1. 誰の、どんな困りごとを解決するのか
- **対象者**: インスペクターを日常的に使うユーザー。
- **困りごと**: Why?・How? の内容は常に全表示されており、把握済みのユーザーには不要な情報量で画面を圧迫することがある。
- **解決策**: 見出しクリックで開閉できるようにし、必要な時だけ展開して使えるようにする。

## 2. 画面とデータの流れ

### アイコンと開閉の対応
| 状態 | 表示アイコン | 意図 |
|------|------------|------|
| 開いている | `ChevronUp`（↑） | 「押せば閉じる」を連想 |
| 閉じている | `ChevronDown`（↓） | 「押せば下に展開される」を連想 |

### 初期状態
- Why?・How? ともに**デフォルトは開いた状態**（既存の表示を維持）

### 開閉状態の管理
- `isWhyOpen`・`isHowOpen` の2つの boolean を **Inspector コンポーネント内の `useState`** で管理する
- Inspector はノード切替時にアンマウント・リマウントされないため、開閉状態はノードをまたいで自然に維持される（ノードAでWhyを閉じた状態でノードBに切り替えてもWhyは閉じたまま）
- Why と How の状態は**独立して管理**する（片方だけ閉じたいニーズが存在するため）

### 実装方法
- 見出し `<h3 className="section-title">` を `onClick` で toggle できるようにする（`cursor: pointer` を CSS に追加）
- 本体コンテンツを `isWhyOpen && ...` / `isHowOpen && ...` で条件レンダリング
- アイコンを open/close の状態に応じて `ChevronUp` / `ChevronDown` に切り替える

## 3. 境界条件

- **Why? がルートゴールの場合**: 「This is a top-level goal.」の1行のみ表示 → 閉じても問題なし
- **How? に子ノードがない場合**: 空状態の点線ボックスを表示 → 閉じても問題なし
- **ノード切替時の開閉状態**: Inspector 内 `useState` のためノードをまたいで維持される（後述「ユーザーからの補足意見」参照）

## 4. 変更スコープ
- **やること**: `Inspector.jsx` に `isWhyOpen`・`isHowOpen` の state 追加 + JSX の条件レンダリング + アイコン切り替え + CSS に `cursor: pointer` 追加
- **やらないこと**: 開閉アニメーション（スムーズな高さ変化）・開閉状態の localStorage 永続化

## ユーザーからの補足意見（仕様策定時の議論より）

> 元の仕様文：「**ノード切替時の開閉状態**: 別ノードを選択してもデフォルト（開）に戻す」

この記述に対し、ユーザーより以下の指摘があった。

### ストレス事象Aについて
複数ノードをまたいで作業している人が、Why?/How? を邪魔に思い閉じたのに、別のノードに移るたびに毎回開いた状態に戻るという体験（**ストレス事象A**）が発生する懸念がある。

> 「途中でwhy how両方が開いている状態を邪魔に思い閉じたのに、別のノードでの作業をやろうと思ったらさっき閉じたのに、また開いている。→邪魔だから閉じよう→別のノードで作業（新しく作成したノード）→また開いてる（怒）→…」

これを防ぐには、開閉状態を複数ノードにまたいで共通で保持する必要がある。`Inspector` 内の `useState` はノード切替時にリセットされないため、この共通管理が自然に実現できる。

### Why と How の状態を分離する理由
上位タスク（子ノードが多い）では How? が縦に長くなりやすく邪魔になりやすい一方、Why? は短くなる。逆に下位タスクでは Why? が長くなりやすい。このように Why と How の「邪魔度」はノードの階層位置によって非対称に変わるため、2つの開閉状態を一緒に保持する設計は避けるべき。`isWhyOpen` と `isHowOpen` を独立した state として管理することで、ユーザーが必要なものだけを個別に閉じられるようにする。

### 仕様の修正結果
| 項目 | 修正前（初期案・誤） | 修正後（確定） |
|------|------------------|--------------|
| ノード切替時の開閉状態 | デフォルト（開）に戻す | ノードをまたいで維持される |
| Why と How の状態管理 | 記述なし | 独立した state として別々に管理 |
