# プラン: コード可読性（命名・構造・コメント）向上

## 全体方針

「可読性 STRATEGY」は以下の順で子タスクを進める。各子タスクは spec.md の改善点一覧の項目番号を参照し、対象ファイルを限定して実施する。

## 子タスクと対応する改善点

1. **可読性の現状レビュー・一覧化**（本タスク）→ spec.md を作成（完了）
2. **treeLogic.js 分割** → H1
3. **ArboristNode 抽出** → H2
4. **Inspector 分割** → H3
5. **App.jsx フック抽出** → H4, H5
6. **ドメイン用語の命名統一** → M6〜M10（＋ M1〜M5 のうち命名部分）
7. **コメント過不足調整** → L1〜L5
8. **整形と最終検証** → L6

## 依存関係

- 子タスク 1（一覧化）がすべての前提。以降は 2→3→4→5 を並行可、6→7→8 はその後に実施。
- H1〜H4 の分割は互いに独立（別ファイル）。順不同で着手可。
- 子タスク 6（命名統一）は 2〜5 の分割後に行うと、分割先ファイルでの置換が一括で行えるため、分割後に着手するのが望ましい。

## 大まかな手順（子タスク 2 以降の共通テンプレート）

1. 対象ファイルの現状を確認する。
2. spec.md の該当改善点を読み、抽出・置換・削除の範囲を確定する。
3. コードを変更する（barrel 禁止・依存一方向性を遵守）。
4. `npm run lint` / `npm run test:run` で検証する。
5. `docs/` を grep し、矛盾する記述があれば連鎖修正する。
6. コミットする。
