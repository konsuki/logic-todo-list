# Node のバージョンを v20+ に固定する（.nvmrc + engines）

## 1. 誰の、どんな困りごとを解決するのか

- **誰**: このプロジェクトを開発・評価する人（開発者自身、および将来の採用担当者）。
- **困りごと**: プロジェクトのツール（Vite 8 / Vitest 4）は Node 20.19+ を要求するが、開発環境のデフォルト Node が v18.12.1 のため、テストが「Node バージョン不足」で起動しない（`node:util` の `styleText` が無いエラー）。毎回手動で nvm を v20 に切り替えないと動かず、環境依存で壊れやすい。Node バージョンをファイルで宣言し、開発環境の再現性を確保する。**アプリ・テストの挙動は一切変えない。**

## 2. 画面やデータの流れ

- 本タスクは設定ファイルの追加のみで、アプリ・テストの実行時挙動に影響しない。
- `.nvmrc` は nvm 利用者が `nvm use` を実行した際に正しい Node へ自動切替するための宣言。
- `package.json` の `engines` は npm 標準のバージョン宣言で、対応外の Node で実行した際に警告を出す。

## 3. 変更内容

### 新規ファイル

| ファイル | 内容 |
| --- | --- |
| `.nvmrc` | `20.19.6` を記載 |

### 変更ファイル

| ファイル | 変更 |
| --- | --- |
| `package.json` | `engines` フィールドを追加し `"node": ">=20.19.0"` を宣言 |

`package.json` の追加位置は既存の `version` の直後（`"type": "module"` の前）とする。

## 4. 普通ではないケース・境界条件

- **`.nvmrc` の値**: 開発環境に実在する v20 の最新（`20.19.6`）を採用し、`nvm use` が確実に切り替えられる値にする。
- **`engines` の記法**: 下限のみ指定（`>=20.19.0`）。v24 などの上位バージョンも許容する。
- **やらないこと**: PC 全体のデフォルト Node 変更（`nvm alias default 20`）は行わない。他プロジェクトへの影響を避けるため、あくまで「このプロジェクトの Node バージョン」をファイルで宣言するだけに留める。
- **`.nvmrc` は自動で読み込まれない**: `.nvmrc` は配置するだけでは有効にならず、`nvm use` の実行が必要（またはシェル連携で自動化）。本タスクでは宣言ファイルの追加までを行い、シェル側の自動化はスコープ外とする。

## 5. 優先順位・本当に必要なもの

- **最優先**: 最小限のファイル追加で Node バージョンを宣言し、開発環境の再現性を確保する。
- **DoD**: `.nvmrc` と `engines` が追加され、Node 20.19.6 で `npm run lint` が exit 0、`npm run test:run` が全件 pass になること。

## 6. 完了の定義（DoD）

- `.nvmrc` がプロジェクト直下に追加され、`20.19.6` と記載されている。
- `package.json` に `engines` が追加され、`"node": ">=20.19.0"` と宣言されている。
- Node 20.19.6 で `npm run lint` / `npm run test:run`（全件 pass）が通る。
